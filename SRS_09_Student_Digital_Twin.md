# Software Requirements Specification (SRS)
## Project 09: Student Digital Twin (Performance + Prediction)

### 1. Project Description
A highly advanced academic analytics platform that creates a "Digital Twin" of a student. By aggregating data from various sources (grades, attendance, library usage, LMS activity), the system builds a comprehensive digital profile. It uses predictive modeling to forecast future performance, identify risks of failing, and suggest specific interventions to improve outcomes.

### 2. Core Scope & Tech Stack
- **Frontend:** ReactJS (Vite), TailwindCSS, MaterialUI (Complex dashboards, 3D/Radar charts).
- **Backend:** Java Spring Boot (Data aggregation, Statistical modeling, REST APIs).
- **Scope:** Heavy data ingestion, data visualization, predictive analytics algorithms, and multi-tier access.

### 3. Functionalities (Minimum 25)

#### Frontend (React + MaterialUI)
1. **The "Digital Twin" Dashboard:** A highly visual homepage displaying the student's current status (GPA, Attendance %, Engagement Score) using custom gauges and radar charts.
2. **Trajectory Graph:** A predictive line chart showing current grade trends and projecting the final semester GPA based on current behavior.
3. **Risk Alerts Panel:** A notification center highlighting specific warnings (e.g., "High Risk of failing Calculus 101 due to missed assignments").
4. **Intervention Action Plan:** A checklist of suggested actions generated by the system (e.g., "Attend Math Tutoring on Thursday").
5. **Historical Comparison:** Toggle to compare the student's current trajectory against their past semesters or the class average.
6. **Data Source Toggles:** Checkboxes to overlay different data points on the main graph (e.g., overlaying "Library Hours" over "Test Scores").
7. **Mobile-Responsive UI:** Ensure advisors can view student profiles easily on tablets during meetings.
8. **Export Profile:** Download the digital twin summary as a comprehensive, multi-page PDF report.

#### Backend (Spring Boot Core Features)
9. **Multi-Role Access:** Spring Security configured for Students (view self), Advisors (view assigned students), and Admins (view all).
10. **Data Ingestion APIs:** Secure endpoints designed to accept bulk data uploads from the university's main LMS (Canvas/Blackboard), Attendance system, and Library.
11. **Data Normalization Service:** Backend logic to clean and standardize data coming from wildly different sources before saving to the database.
12. **Predictive Scoring Engine:** A Java service applying statistical weights (or calling an external Python ML service) to calculate the "Failure Risk Score".
13. **Event Trigger System:** Logic that automatically fires an email to the academic advisor if a student's Risk Score crosses a critical threshold.
14. **CRUD for Interventions:** Endpoints for advisors to log notes and assign mandatory interventions to a student's profile.

#### Advanced Analytics & Modeling
15. **"What-If" Simulator:** An API endpoint that allows the frontend to send hypothetical data (e.g., "What if I get an 80 on the final?") and returns the recalculated predicted GPA.
16. **Peer Clustering:** Algorithm that compares the student to historically similar students to improve the accuracy of predictions.
17. **Engagement Metric Calculation:** Aggregate logins to the LMS, forum posts, and assignment submission times to generate a single "Engagement Score".
18. **Sentiment Tracking:** (Optional) If students submit weekly reflections, run basic sentiment analysis to track emotional well-being over the semester.

#### Privacy, Security, & System Architecture
19. **FERPA Compliance Features:** Ensure strict data access logs (Spring Data Envers) so admins know exactly which advisor viewed which student's data.
20. **Data Anonymization Export:** Provide an endpoint to export a massive dataset of all students with identifying info scrubbed, useful for university research.
21. **Scheduled Aggregation:** Spring `@Scheduled` tasks that run nightly to recalculate the massive Risk Scores to avoid doing heavy math during active daytime requests.
22. **Database Sharding/Indexing:** Optimize JPA queries to handle millions of data points (every assignment grade for every student) efficiently.
23. **Two-Factor Authentication (2FA):** Enforce 2FA for advisors and admins accessing sensitive student data.
24. **Cache Management:** Implement Redis caching for the most frequently viewed student dashboards to improve load times.
25. **Admin Monitoring Dashboard:** View overall system health, data ingestion success rates, and API latency.
